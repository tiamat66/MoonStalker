================================================================================
  MoonStalker Drive Unit - Serial Command Interface Documentation
================================================================================

  Author  : MoonStalker Project
  Hardware: ATmega32u4 (Arduino Micro)
  Serial  : Serial (USB), 115200 baud

  All commands and responses are enclosed in angle brackets '<' and '>'.
  The '>' character signals end of command and triggers processing.
  Parameters are space-separated.

--------------------------------------------------------------------------------
  TABLE OF CONTENTS
--------------------------------------------------------------------------------

  1.  <MV>            - Move (finite step movement)
  2.  <MVS>           - Move Start (free run / continuous movement)
  3.  <MVE>           - Move End (stop free run)
  4.  <STOP>          - Emergency stop
  5.  <BTRY?>         - Query battery voltage
  6.  <MVST?>         - Query motor status
  7.  <LIM?>          - Query limit switch states
  8.  <ALARMS?>       - Query alarms (system check)
  9.  <COORDS?>       - Query signed coordinate positions
  10. <STEP_COUNTER?> - Query cumulative step counters
  11. <STEP_COUNTER_RESET> - Reset step counters and coordinates
  12. <DEBUG>         - Debug information
  13. Automatic / Unsolicited Responses
  14. Error Responses


================================================================================
  1.  <MV> - Move (finite step movement)
================================================================================

  Command:
    <MV horiz_steps vert_steps rpm_speed>

  Description:
    Moves both axes by the specified number of steps at the given speed.
    The sign of horiz_steps and vert_steps determines direction:
      positive = CW, negative = CCW.
    The motors run for exactly the specified number of steps and then stop
    automatically. The controller transitions back to IDLE_MODE when both
    axes have completed their step counts.
    Ramping (acceleration/deceleration) applies as configured via the
    set_ramp_steps() method (default: 100 steps). The ramp is capped at half
    an axis's step count, and is skipped entirely for an axis whose speed is
    already at or below the ramp's start speed (~18.75 RPM at 200 steps per
    revolution), since there would be nothing to accelerate from.

  Parameters:
    horiz_steps  : int  - Number of azimuth steps. Positive = CW, negative
                          = CCW. Zero = no horizontal movement.
                          Range -32767..32767.
    vert_steps   : int  - Number of altitude steps. Positive = CW, negative
                          = CCW. Zero = no vertical movement.
                          Range -32767..32767.
    rpm_speed    : int  - Motor speed in revolutions per minute. Applied to
                          both axes. Must be > 0 and <= 32767.

    At least one of horiz_steps and vert_steps must be non-zero.

  Example:
    <MV 200 100 60>   Move 200 steps horizontal CW, 100 steps vertical CW,
                      at 60 RPM.
    <MV -200 50 30>   Move 200 steps horizontal CCW, 50 steps vertical CW,
                      at 30 RPM.

    Prerequisite:
    Controller must be in IDLE_MODE.

    Responses:
    <MV_ACK horiz_steps vert_steps rpm_speed>
      Sent immediately upon accepting the command, before movement starts.

    <MV_NACK LIMIT_BLOCKED>
      Sent instead of <MV_ACK> if a limit switch is pressed in the direction
      of travel. No movement occurs.

    <MV_NACK NOT_RDY>
      Sent if not in IDLE_MODE (a move or free run is already in progress).

    <MV_NACK BAD_PARAMS>
      Sent if any of the three parameters is missing, if rpm_speed is not
      greater than zero, or if any parameter is outside its valid range.
      No movement occurs.

    <MV_NACK NO_MOVEMENT>
      Sent if both horiz_steps and vert_steps are zero. The command is
      rejected rather than accepted as a no-op, because a zero-step move
      would leave the controller in MOVE_MODE with no motion to end it.


================================================================================
  2.  <MVS> - Move Start (free run / continuous movement)
================================================================================

  Command:
    <MVS direction rpm_speed>

  Description:
    Starts continuous (free run) movement in the specified direction at the
    given speed. The motors run indefinitely until <MVE> or <STOP> is sent;
    there is no step limit or timeout on a free run.
    Ramping (acceleration) applies as configured via
    set_free_run_ramp_steps() (default: 50 steps). As with <MV>, the ramp is
    skipped for a speed already at or below the ramp's start speed
    (~18.75 RPM at 200 steps per revolution).

  Parameters:
    direction  : string - One of the eight cardinal and intercardinal
                          directions:
       N   - North  (vertical CW)
       S   - South  (vertical CCW)
       W   - West   (horizontal CW)
       E   - East   (horizontal CCW)
       NW  - North-west  (vertical CW + horizontal CW)
       NE  - North-east  (vertical CW + horizontal CCW)
       SW  - South-west  (vertical CCW + horizontal CW)
       SE  - South-east  (vertical CCW + horizontal CCW)

    rpm_speed : int - Motor speed in RPM. Must be > 0 and <= 32767.

  Example:
    <MVS N 30>      Move North (vertical CW) at 30 RPM.
    <MVS NE 60>     Move North-East at 60 RPM (both axes).
    <MVS W 120>     Move West (horizontal CW) at 120 RPM.

    Prerequisite:
    Controller must be in IDLE_MODE.

    Responses:
    <MVS_ACK direction rpm_speed>
      Sent upon accepting the command. Movement begins immediately.

    <MVS_NACK LIMIT_BLOCKED>
      Sent instead of <MVS_ACK> if a limit switch is pressed in the direction
      of travel. No movement occurs.

    <MVS_NACK NOT_RDY>
      Sent if not in IDLE_MODE. Must stop first with <MVE> or <STOP>.

    <MVS_NACK UNKNOWN_DIRECTION>
      Sent if the direction string is not one of: N, S, W, E, NW, NE, SW, SE.

    <MVS_NACK BAD_PARAMS>
      Sent if the direction or rpm_speed parameter is missing, or if
      rpm_speed is not greater than zero. No movement occurs.


================================================================================
  3.  <MVE> - Move End (stop free run)
================================================================================

  Command:
    <MVE>

  Description:
    Stops free run (continuous) movement. The motors decelerate smoothly
    over free_run_ramp_steps (default: 50) and then stop. Once the ramp-down
    is complete, the controller transitions to IDLE_MODE automatically.
    An axis already running at or below the ramp's start speed
    (~18.75 RPM at 200 steps per revolution) stops immediately instead,
    since it is already slow enough to stop without decelerating.

  Parameters:
    None.

  Prerequisite:
    Controller must be in FREE_RUN_MODE.

  Responses:
    <MVE_ACK>
      Sent upon accepting the stop command. The motors begin decelerating
      immediately. The actual stop occurs after the ramp-down completes
      (a few hundred milliseconds at typical speeds).

    <MVE_NACK NOT_RDY>
      Sent if not in FREE_RUN_MODE.


================================================================================
  4.  <STOP> - Emergency stop
================================================================================

  Command:
    <STOP>

  Description:
    Immediately halts all motor movement, regardless of current mode
    (FREE_RUN or MOVE). Calls the consolidated emergency_stop() routine
    which atomically disables timer interrupts, clears step counts, pulls
    step pins low, and resets all ramp state. Any pending free-run
    ramp-down is cancelled. The controller immediately transitions to IDLE_MODE.

  Parameters:
    None.

  Responses:
    <STOP_ACK>
      Sent after the stop is complete. The motors stop instantly
      (no ramp-down).


================================================================================
  5.  <BTRY?> - Query battery voltage
================================================================================

  Command:
    <BTRY?>

  Description:
    Reads the battery voltage through a voltage divider on analog pin A0.
    The ADC value is converted to millivolts, accounting for the divider
    ratio (5.088 kohm / 14.93 kohm).

  Parameters:
    None.

  Responses:
    <BTRY voltage_mv>
      voltage_mv : int - Battery voltage in millivolts (mV).
        Example: <BTRY 12400>  means 12.4 V


================================================================================
  6.  <MVST?> - Query motor status
================================================================================

  Command:
    <MVST?>

  Description:
    Queries the current state of the stepper controller. Returns one of
    three possible states: IDLE (motors stopped, ready for commands),
    MOVING (finite step move in progress), or FREE_RUN (continuous
    rotation in progress). The controller automatically transitions
    back to IDLE when a move completes or a free-run ramp-down finishes.

  Parameters:
    None.

  Responses:
    <MVST IDLE>
      Controller is in IDLE_MODE. Motors are stopped. Ready for <MV> or
      <MVS>.

    <MVST MOVING>
      Controller is in MOVE_MODE. A finite step move (<MV>) is in progress.
      The controller will transition to IDLE automatically when all steps
      complete. Use <STOP> to interrupt.

    <MVST FREE_RUN>
      Controller is in FREE_RUN_MODE. Continuous rotation (<MVS>) is active.
      Use <MVE> to stop with smooth deceleration, or <STOP> for immediate
      stop.


================================================================================
  7.  <LIM?> - Query limit switch states
================================================================================

  Command:
    <LIM?>

  Description:
    Reads and reports the current state of all four limit switches.
    This is an informational command only - it does not stop the motors.
    Each switch name is printed in UPPERCASE if active (pressed / pin LOW)
    or lowercase if inactive (not pressed / pin HIGH).

  Parameters:
    None.

  Responses:
    <LIM HORIZ_WEST horiz_east vert_north VERT_SOUTH>
      Four switch names, each either UPPERCASE or lowercase:
        HORIZ_WEST  - West azimuth limit
        HORIZ_EAST  - East azimuth limit
        VERT_NORTH  - North altitude limit
        VERT_SOUTH  - South altitude limit
      Example: <LIM HORIZ_WEST horiz_east vert_north VERT_SOUTH>
        Means: HORIZ_WEST and VERT_SOUTH are pressed,
               HORIZ_EAST and VERT_NORTH are not pressed.


================================================================================
  8.  <ALARMS?> - Query alarms (system check)
================================================================================

  Command:
    <ALARMS?>

  Description:
    Checks the system for any error conditions and returns the results
    in a single response. Checks the battery voltage and the fault status
    of both DRV stepper drivers. Any detected issues are reported as alarm
    keywords inline within the response.

  Parameters:
    None.

    Response:
      <ALARMS [ALARM_LOW_BTRY] [ALARM_DRV_HORIZ_FAULT] [ALARM_DRV_VERT_FAULT]
              [ALARM_LIMIT_HORIZ_WEST_ACTIVE] [ALARM_LIMIT_HORIZ_EAST_ACTIVE]
              [ALARM_LIMIT_VERT_NORTH_ACTIVE] [ALARM_LIMIT_VERT_SOUTH_ACTIVE]>

      ALARM_LOW_BTRY                 : Present if battery voltage < 10000 mV (10.0 V).
      ALARM_DRV_HORIZ_FAULT          : Present if horizontal DRV fault pin is LOW.
      ALARM_DRV_VERT_FAULT           : Present if vertical DRV fault pin is LOW.
      ALARM_LIMIT_HORIZ_WEST_ACTIVE  : Present if horizontal west limit switch is pressed.
      ALARM_LIMIT_HORIZ_EAST_ACTIVE  : Present if horizontal east limit switch is pressed.
      ALARM_LIMIT_VERT_NORTH_ACTIVE  : Present if vertical north limit switch is pressed.
      ALARM_LIMIT_VERT_SOUTH_ACTIVE  : Present if vertical south limit switch is pressed.

      Examples:
        <ALARMS>
          No alarms, system healthy.
        <ALARMS ALARM_LOW_BTRY>
          Low battery alarm active.
        <ALARMS ALARM_DRV_HORIZ_FAULT ALARM_LIMIT_HORIZ_EAST_ACTIVE>
          Horizontal driver fault and east limit switch triggered.


================================================================================
  9.  <COORDS?> - Query signed coordinate positions
================================================================================

  Command:
    <COORDS?>

  Description:
    Queries the current signed coordinate positions for both axes.
    coord_x is incremented for CW horizontal movement and decremented for
    CCW horizontal movement. coord_y is incremented for CW vertical movement
    and decremented for CCW vertical movement.
    These coordinates can be used to track the absolute position of the
    telescope on the sky. They are reset to zero by the <STEP_COUNTER_RESET>
    command or on system power-up.

  Parameters:
    None.

  Responses:
    <COORDS X:x Y:y>
      x : int32 - Signed horizontal coordinate.
                  Positive = CW (west), negative = CCW (east).
      y : int32 - Signed vertical coordinate.
                  Positive = CW (north), negative = CCW (south).
      Example: <COORDS X:1250 Y:-300>
        Means: 1250 steps CW from origin horizontally,
               300 steps CCW from origin vertically.


================================================================================
  10. <STEP_COUNTER?> - Query cumulative step counters
================================================================================

  Command:
    <STEP_COUNTER?>

  Description:
    Queries the cumulative total of all steps executed on each axis since
    the last reset or system start. These counters are unsigned and always
    increment regardless of direction. Each physical step executed by the
    motor increments the counter by one.
    Unlike coord_x / coord_y (which are signed and cancel direction),
    step counters provide an absolute measure of total motor wear or
    distance traveled.

  Parameters:
    None.

  Responses:
    <STEP_COUNTER X:x Y:y>
      x : uint32 - Cumulative horizontal steps (always positive).
      y : uint32 - Cumulative vertical steps (always positive).
      Example: <STEP_COUNTER X:15234 Y:9876>
        Means: 15234 total horizontal steps and 9876 total vertical
               steps have been executed since last reset.


================================================================================
  11. <STEP_COUNTER_RESET> - Reset step counters and coordinates
================================================================================

  Command:
    <STEP_COUNTER_RESET>

  Description:
    Resets the step counters (step_counter_x, step_counter_y) and the
    signed coordinate positions (coord_x, coord_y) to zero.
    This is used to re-establish a known home position after mechanical
    calibration or re-homing. The reset is performed atomically with
    interrupts disabled to ensure both counters are cleared together.

  Parameters:
    None.

  Responses:
    <STEP_COUNTER_RESET_ACK>
      Sent after successfully resetting all counters to zero.
      Example: <STEP_COUNTER_RESET_ACK>


================================================================================
  12. <DEBUG> - Debug information
================================================================================

  Command:
    <DEBUG>

  Description:
    Reports the current step counters for both axes. Useful for diagnostics
    and testing. Only reports data when not in FREE_RUN_MODE (free run holds
    steps_remain at 65535, which is meaningless for debugging).

  Parameters:
    None.

  Responses:
    <MV_REMAIN X: horiz_steps Y: vert_steps>
      Steps remaining on each axis.

    <MV_CURRENT X: horiz_steps Y: vert_steps>
      Steps completed so far on each axis since the last command start.
      Resets to 0 on each new <MV> or <MVS> command.

    <DEBUG_NA FREE_RUN>
      Sent instead of the two responses above when in FREE_RUN_MODE, so a
      client waiting on a reply is not left hanging.


================================================================================
  13. AUTOMATIC / UNSOLICITED RESPONSES
================================================================================

  These responses are generated by the system automatically, not in direct
  response to a command.

  <INFO System start>
    Sent once on boot / setup completion.

  <INFO Handling command: <...>>
    Sent before processing any incoming command (echo for debugging).

  <FATAL_ERROR RCV_BUFFER_OVERFLOW>
    Sent if the incoming command buffer (64 characters) is exceeded.
    The controller then discards the remaining bytes of that command until
    its terminator ('>') or a newline arrives, and resumes normal operation.
    The truncated command is never executed. The discard runs one byte per
    main loop iteration, so limit switch monitoring continues uninterrupted
    even if the sender stalls in the middle of an oversized command.

  <LIMIT HORIZ_WEST>  (or HORIZ_EAST, VERT_NORTH, VERT_SOUTH)
    Sent automatically when an axis moves into a pressed limit switch.
    A 2-sample debounce filter is applied: the limit must be pressed for
    two consecutive loop iterations (~sub-millisecond) before triggering.
    The motors are stopped via emergency_stop() (equivalent to <STOP>).
    Multiple switch names can appear if more than one axis is driving into
    a limit.

    The check is direction-aware and uses the same mapping the <MV> and
    <MVS> handlers apply before starting a move (horizontal CW = west,
    horizontal CCW = east, vertical CW = north, vertical CCW = south).
    A pressed limit therefore does NOT stop a move that is driving away
    from it, which is what allows the telescope to be backed off a switch
    once it has been hit. Use <LIM?> or <ALARMS?> to see every pressed
    switch regardless of direction of travel.

    Note that the stop halts both axes, so a diagonal move that drives only
    one axis into a limit stops the other axis as well.

  <INFO Initial OCR1A: value> and <INFO Initial OCR3A: value>
    Sent once during timer initialization at boot. Reports the initial OCR
    value set for each timer. For diagnostic purposes only.


================================================================================
  14. ERROR RESPONSES
================================================================================

  These responses can be returned by multiple commands.

    <MV_NACK reason> / <MVS_NACK reason> / <MVE_NACK reason>
      Negative acknowledgment for the MV, MVS or MVE command. The reason field
      indicates the specific error:
        NOT_RDY            - The controller is busy with another operation.
        LIMIT_BLOCKED      - The movement would travel toward a pressed limit.
        UNKNOWN_DIRECTION  - (MVS only) Invalid direction string.
        BAD_PARAMS         - A required parameter is missing, out of range,
                             or rpm_speed is not greater than zero.
        NO_MOVEMENT        - (MV only) Both step counts are zero.

  <ERR UNKNOWN_COMMAND tag>
    The command tag is not recognised. The tag as received is echoed back.
    Sent so that a client is always answered, even for a malformed command.

  <LIMIT HORIZ_WEST>  (and variants)
    An axis moving into an active limit switch triggered an emergency stop.
    Sent automatically by the check_limit_switches() polling function.
